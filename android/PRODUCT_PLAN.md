# DropLink 安卓版 · 产品与技术方案

> 版本：v1.0 方案稿 · 日期：2026-11-03  
> 定位：局域网「扫码即连」的极速文件互传 App —— 手机⇄手机、手机⇄电脑，零流量、零云端、零压缩。

---

## 1. 核心定位与目标用户

### 1.1 一句话定位

**「扫码即连的局域网文件直通车」** —— 不经过互联网、不上传云端、不压缩画质，原图原文件点对点传输。

### 1.2 目标用户与场景

| 用户群        | 核心痛点               | 典型场景                |
| ---------- | ------------------ | ------------------- |
| 学生 / 宿舍党   | 校园网 AP 隔离、流量贵、微信压图 | 手机互传课件、照片、视频；传电脑交作业 |
| 办公 / 职场人   | 网盘限速、微信大小限制、隐私顾虑   | 手机电脑互传文档、大附件        |
| 摄影 / 视频创作者 | 原图无损、大文件、批量        | 手机原片传电脑、多设备分发素材     |
| 换机 / 多设备用户 | 迁移麻烦、数据线繁琐         | 新旧手机互传、批量搬迁         |

### 1.3 差异化优势

1. **扫码即连**：扫二维码直接建立连接，无需账号、无需输入 IP；
2. **零流量**：纯局域网，不耗手机移动数据；
3. **无损原速**：不压缩、不转码、无单文件大小限制，跑满 Wi-Fi 带宽；
4. **隐私安全**：文件不出局域网，配对码鉴权，删除进回收站；
5. **一台开热点即可互传**：无 Wi-Fi 环境下，一台手机开热点，另一台连接即可，摆脱路由器。

## 2. 核心功能模块

### 2.1 连接与配对

- **扫码连接**：扫电脑端 / 另一台手机的连接二维码，自动打开地址并输入配对码；
- **二维码展示**：本机生成连接二维码（含 IP + 端口 + 配对码）；
- **6 位配对码**：首次连接鉴权，连续输错 5 次锁定 1 分钟，配对后 30 天免输；
- **热点模式**：一键开启移动热点，另一台连接后组成临时局域网。

### 2.2 文件传输

- **浏览**：文件列表（图标/缩略图）、进入子目录、路径导航、搜索；
- **上传**：相册多选、文件选择器、拍照、整个文件夹；
- **下载**：下载确认页（文件名/大小/下载按钮/保存位置）、选择保存目录；
- **分享**：生成二维码 + 链接，24 小时有效，扫码直接下载；
- **批量**：长按多选、打包 zip、批量下载；
- **传输中心**：实时速度曲线、数据流粒子动画、进度环、完成动效（与电脑版一致）；
- **断点续传**：大文件中断续传，`.part` 临时文件管理。

### 2.3 剪贴板

两端互发文字 / 链接，复制粘贴不用重新输入；历史记录、一键复制、删除。

### 2.4 设备与通知

- **已接入设备**：实时显示连接中的终端数量；
- **接入提示**：有新设备连上时系统通知 + 应用内 toast；
- **接收目录**：自定义文件保存位置。

### 2.5 设置与体验

- 深色 / 浅色主题（跟随系统）；
- 首次使用图文引导（3 步）；
- 每个功能页的小字提醒（怎么用 + 连不上怎么办）。

## 3. 技术架构与实现路径

### 3.1 技术选型

| 层       | 选型                                   | 理由                                 |
| ------- | ------------------------------------ | ---------------------------------- |
| 语言      | Kotlin                               | Android 官方首选，空安全、协程                |
| UI      | WebView 加载内置 assets + Material 3 原生壳 | 复用现有 web UI，动画/主题/引导零重做，风格 100% 一致 |
| HTTP 服务 | 自研精简 Server（ServerSocket + 线程池）      | 零第三方依赖、可控、可裁剪，移植 server.py 逻辑      |
| 二维码     | ZXing core                           | 纯 Java 离线，生成 + 解码一体，无 Google 服务依赖  |
| 热点      | WifiManager 反射 + LocalOnlyHotspot    | 覆盖 Android 8~15 各版本差异              |
| 文件      | SAF + MediaStore                     | 适配 Android 10+ 分区存储                |
| 构建      | Gradle + AGP                         | 标准方案                               |
| 最低 SDK  | API 26 (Android 8.0)                 | 覆盖 95%+ 设备                         |
| 目标 SDK  | API 34 (Android 14)                  | 最新稳定                               |

### 3.2 分层架构（见架构图）

- **UI 层**：WebView 加载内置 `index.html`/`app.js`/`styles.css`，动画、主题、引导全部复用；
- **桥接层**：`JavascriptInterface` 暴露原生能力给 web（扫码、开热点、文件选择、系统通知、剪贴板）；
- **服务层**：内置 HTTP Server 实现 `/api/*`（session/list/upload/download/share/clip…）+ ZXing + 热点管理；
- **数据层**：SAF/MediaStore 文件访问 + SharedPreferences 轻量持久化。

### 3.3 实现路径（4 个里程碑）

| 里程碑   | 内容                                 | 交付物               |
| ----- | ---------------------------------- | ----------------- |
| M1 骨架 | 环境搭建 + 项目骨架 + WebView 加载 UI + JS 桥 | 可运行的 App 壳，界面完整展示 |
| M2 服务 | 内置 HTTP Server + 文件列表/上传/下载/分享     | 手机可自托管文件服务        |
| M3 连接 | 扫码 + 二维码生成 + 热点 + 配对码              | 手机互传、连电脑全链路打通     |
| M4 打磨 | 剪贴板、通知、断点续传、性能/安全、签名打包             | 可分发安装的 APK        |

### 3.4 关键工程决策

1. **UI 用 WebView 复用，不重写原生界面** —— 这是"风格一致 + 动画一致"成本最低、效果最稳的路径；
2. **HTTP Server 自研而非引 NanoHTTPD** —— 完全掌控接口行为，与现有 server.py 逐一对齐，避免第三方库行为差异；
3. **扫码用 ZXing 而非 ML Kit** —— 国内手机无 Google Play 服务，ZXing 离线可用、体积小；
4. **App 双角色** —— 既是"主机"（开热点 + 提供文件服务）也是"客户端"（扫码连别人），与电脑版同构。

## 4. UI / UX 设计要点

1. **风格统一**：完全复用现有 web UI 的配色（紫→紫罗兰渐变）、圆角、图标、间距，电脑版手机版观感一致；
2. **动画一致**：传输中心的粒子数据流、速度波形、进度环、完成波纹全部复用，维持 120fps 优化（零分配渲染）；
3. **深色 / 浅色**：跟随系统，手动切换记忆偏好；
4. **首次引导**：3 步图文引导（这是什么 → 怎么连 → 怎么传），看完不重复弹；
5. **功能小字提醒**：每个功能页顶部一条"怎么用 + 不行怎么办"；
6. **手势与反馈**：长按多选、下拉刷新、按钮按压缩放、接入设备 toast；
7. **Material 3 原生壳**：启动页、系统权限请求、扫码页、设置页用原生，符合 Android 平台习惯；
8. **可访问性**：最小字号 11px、深色模式对比度达标、`prefers-reduced-motion` 尊重系统减弱动效偏好。

## 5. 性能与安全优化策略

### 5.1 性能

- **渲染**：WebView 硬件加速、`setLayerType(LAYER_TYPE_HARDWARE)`；canvas 动画保持零分配（沿用现有优化）；
- **传输**：HTTP Server 分块流式读写（`Content-Length` + 流式发送）、大文件不整块载入内存；上传边收边写磁盘（`.part` 续传）；
- **缩略图**：图片缩略图本地按需生成 + 缓存，避免 OOM；
- **内存**：WebView 生命周期管理（`onPause`/`onResume` 暂停渲染）、文件流及时关闭；
- **电量**：空闲时降采样/暂停动画，前台服务仅传输时保持。

### 5.2 安全

- **局域网限定**：HTTP Server 只监听热点/局域网网段，拒绝公网；
- **配对码鉴权**：6 位随机码 + 防爆破（5 次锁定 1 分钟）+ 会话 token（HttpOnly cookie，30 天）；
- **分享 token**：24 小时过期、随机 12 字节、不可预测；
- **路径穿越防护**：文件名净化、`..` 过滤、只允许访问接收目录；
- **删除进回收站**：可恢复，杜绝误删永久丢失；
- **权限最小化**：仅在需要时请求（存储/相机/定位-热点），拒绝时优雅降级；
- **传输内容不落云端**：全程 P2P 局域网，无任何服务器中转。

## 6. 部署发布流程

1. **构建**：Gradle 打包 `assembleRelease`，`minifyEnabled + R8` 混淆压缩，生成瘦身 APK；
2. **签名**：生成 keystore，release 签名（V2/V3 签名）；
3. **体积控制**：复用 web 资源 + ZXing core + 自研 server，目标 APK ≤ 8MB；
4. **自测**：真机安装冒烟（扫码、互传、热点、权限流转），模拟器回归核心链路；
5. **分发（第一阶段）**：直接交付签名 APK，用户侧载安装（符合当前"自己用 + 给舍友用"场景）；
6. **分发（第二阶段，可选）**：上架国内应用商店（需软著/备案）或 GitHub Releases；
7. **版本管理**：语义化版本 + 构建产物归档，保留 keystore 备份。

## 7. 风险与应对

| 风险                     | 应对                                                     |
| ---------------------- | ------------------------------------------------------ |
| Android 热点 API 各版本差异   | 反射 + 版本分支 + LocalOnlyHotspot 兜底                        |
|                        |                                                        |
| Android 10+ 分区存储限制     | SAF + MediaStore + `requestLegacyExternalStorage` 兼容旧机 |
| WebView 版本差异           | 最低 WebView 内核检测 + 提示升级                                 |
| 国产 ROM 后台限制（热点/前台服务被杀） | 前台服务 + 省电白名单引导                                         |
| 扫码相机权限被拒               | 引导到系统设置，或提供手动输入地址降级                                    |
