## 一、先看清差距：LocalSend 有什么，DropLink 有什么

| 能力 | LocalSend | DropLink 现状 | 差距 |
|---|---|---|---|
| 传输加密 | HTTPS/TLS，首次启动自签证书 | **明文 HTTP/1.1** | 全缺 |
| 设备身份 | 证书 SHA-256 指纹即设备 ID，改名不改指纹 | 无设备身份，只有一个配对码 | 全缺 |
| 首次信任 | 首次连接需接收方确认，记录指纹 | 输对配对码即全权 | 缺确认环节 |
| 传输确认 | 先发元数据 → 人工接受 → 才传字节 | **鉴权后直接落盘**（`api.py:809`） | 缺整层 |
| 逐文件授权 | 每文件一次性 token，绑 session | 会话级 Cookie 全权 | 缺细粒度 |
| PIN | 6 位，错→401 | 4–8 位（加固 8–12），错→403，5 次退避 | 已有，语义待对齐 |
| 完整性 | 可选 SHA-256，不符→422 | `/api/sha256` 有，但下载不强制校验 | 半有 |
| 路径安全 | 只写接收目录 | 个人模式可读整机（`fsutil.py:111`） | 边界待定 |
| 明文回退 | 浏览器回退用 HTTP，**明说**了 | 全程 HTTP，未提示 | 需显式化 |
| 发布完整性 | Windows 二进制代码签名 | EXE 未签名，APK 仅 v2 | 缺 |

**一句话**：DropLink 现在是「配对码 = 一次性全权」，LocalSend 是「每次传输都要过一道人工闸门」。加固的核心不是加算法，是**把「一对全权」拆成「设备身份 + 逐次授权」**。

## 三、逐条说明（派工用）

### S-01 TLS 传输加密（P0，3 人日）
- **做什么**：服务启动时若无证书则生成自签证书（RSA-2048 或 ECDSA P-256），持久化到配置目录；HTTP 服务改为 TLS 监听；保留一个仅本机可用的明文端口供桌面端内部调用（可选）。
- **实现要点**：Python 标准库 `ssl.SSLContext` + `cryptography` 不可用则用 `ssl` + 外部 openssl 生成。证书含 SAN：`localhost`、当前局域网 IP、主机名。私钥文件权限 0600（Windows 用 ACL 限制到当前用户）。
- **验收标准**：① `openssl s_client` 能完成握手；② 浏览器打开 `https://IP:8848` 出现证书警告（自签属预期）；③ 明文端口不可从局域网访问；④ 证书重启后不变（不是每次重新生成）。
- **别做**：不要试图申请公网 CA 证书；不要为了「不弹警告」而关闭校验。

### S-02 证书指纹 = 设备身份 + 信任列表（P0，3 人日）
- **做什么**：计算本机证书 SHA-256 指纹，作为设备 ID 展示（前 8 位可读，如 `A1B2-C3D4`）；对端首次连接时记录其指纹；维护「已信任设备」列表（名称、指纹、首次时间、最后时间），支持撤销。
- **实现要点**：指纹存 `trusted_devices.json`；名称可变、指纹不可变，UI 要显示两者；指纹变化时**必须告警**而不是静默更新（防中间人）。
- **验收标准**：① 两台设备互连后各自列表出现对方；② 手工改动对端证书后，再次连接触发「指纹不一致」告警并拒绝；③ 撤销后需重新确认才可再连。

### S-03 传输前人工确认（P0，4 人日）——**最重要的一条**
- **做什么**：把「鉴权后直接落盘」改成两阶段：
  1. `POST /api/prepare-upload`：只发元数据（文件名、大小、MIME、可选 SHA-256），接收端弹窗显示「谁、要传什么、多大」；
  2. 用户接受 → 返回 `sessionId` + 每文件 token；拒绝 → 403；超时 → 408；
  3. 真正上传走 `POST /api/upload?sessionId=&fileId=&token=`。
- **实现要点**：保留旧 `/api/upload` 但**默认关闭**，仅在「自动接受」开关打开且对端在信任列表时可用；「自动接受」默认关，UI 要写清风险。
- **验收标准**：① 未确认前，接收目录不出现任何文件（含 `.part`）；② 拒绝后发送方收到 403 且无法绕过；③ 弹窗信息与实际文件一致（名称、大小）；④ 一次会话只能确认一次，重放无效。
- **兼容性**：安卓 App 与 Web UI 都要改；旧客户端连新服务端时给出明确降级提示，不要静默失败。

### S-04 逐文件一次性 token（P0，2 人日）
- **做什么**：token 绑定 `sessionId + fileId`，用后即废；跨文件复用返回 403。
- **验收标准**：① A 文件的 token 传 B 文件被拒；② 同一 token 二次使用被拒；③ token 过期（建议 10 分钟）后失效。

### S-05 授权语义对齐（P0，1 人日）
- **做什么**：统一状态码 —— 未认证 401、已认证但无权限/被拒 403、会话不存在或过期 409/410、PIN 错 401、校验不符 422、限流 429（带 `Retry-After`）。
- **验收标准**：错误码表进 README；每个码都有对应用例；客户端能据此给出人话提示。

### S-06 路径与写入安全（P0，2 人日）
- **做什么**：写入侧只允许落在接收目录内（`os.path.realpath` 后再判包含）；拒绝 UNC（`\\?\`、`\\server\`）、ADS（`file.txt:stream`）、符号链接/目录联接、Windows 保留名（CON/PRN/AUX/NUL/COM1-9/LPT1-9）、结尾点与空格；文件名长度上限；Unicode NFC 归一化后再判重。
- **验收标准**：① `../`、`..\`、`%2e%2e%2f`、双重编码全部拦截；② 建符号链接指向 `C:\Windows` 后上传仍被拒；③ `CON.txt`、`a.txt:ads` 被拒；④ 超长名（>255）报 400 不崩。
- **注意**：读取侧（浏览整机）是产品既有能力，本轮**不改**，但要在文档里写清边界（见 S-16）。

### S-07 分接口限流与锁定（P1，1.5 人日）
- **做什么**：登录按 IP + 全局双维度计数（已有 5 次退避，保留）；上传按会话计并发与速率；列目录/预览按 IP 限 QPS；429 带 `Retry-After`。
- **验收标准**：① 单 IP 每秒 50 次列目录触发 429；② 并发上传超过 N 被拒而不是拖垮服务；③ 退避时间符合 60→120→240 上限 300 秒。

### S-08 明文降级显式化（P1，0.5 人日）
- **做什么**：若保留 HTTP 回退（浏览器兼容），在页面顶部常驻一条「当前连接未加密」提示，并在 README 单列一节说明取舍（与 LocalSend 的浏览器回退同一性质）。
- **验收标准**：HTTP 访问必然出现提示；HTTPS 访问不出现；提示不可被 localStorage 永久关闭。

### S-09 密钥与凭据存储（P1，1 人日）
- **做什么**：私钥、`trusted_devices.json`、`config.json` 统一放用户配置目录；私钥仅当前用户可读；不进日志、不进崩溃转储；安卓端用 Keystore 存私钥。
- **验收标准**：① 其他用户账户读不到私钥；② 日志与 `--selfcheck` 输出不出现私钥/PIN/token；③ 打包产物里不含私钥。

### S-10 日志脱敏（P1，1 人日）
- **做什么**：日志中路径只留文件名 + 哈希前缀；IP 保留网段掩码（`192.168.1.*`）；PIN 与 token 一律 `***`；异常栈保留但过滤用户目录。
- **验收标准**：全文搜索日志无完整路径、无 PIN、无 token；排障所需信息仍够用（能定位文件与时间）。

### S-11 磁盘配额与残留清理（P1，1 人日）
- **做什么**：接收目录设配额（默认不限制但可配）；`.part` 超 24 小时清理（已有）；上传中断要能续或明确作废；磁盘不足返回 507 而非半截文件。
- **验收标准**：① 配额满时拒绝并提示；② 断电重启后 `.part` 不残留超过 24 小时；③ 507 之后无 0 字节文件。

### S-12 恶意输入（P1，1.5 人日）
- **做什么**：压缩包下载防 zip 炸弹（条目数、解压比、总大小三重限制）；超长文件名与深层目录（>32 层）拒绝；MIME 与扩展名不一致时不自动执行；预览只读前 N KB（已有）。
- **验收标准**：① 构造 1000:1 压缩比的文件被拒；② 32 层嵌套目录被拒；③ 预览不加载整个大文件。

### S-13 Web 面加固（P1，1.5 人日）
- **做什么**：Cookie 加 `Secure`（TLS 下）；加固 Host/Origin 校验在**默认模式也开**（现在只在 `--secure`）；DNS rebinding 防护（校验 Host 必须是本机 IP/主机名）；静态资源加 `X-Content-Type-Options: nosniff`、CSP 最小集。
- **验收标准**：① 伪造 Host 的请求被拒；② 跨站表单提交被 SameSite + Origin 双层拦截；③ 响应头齐全（可用 `curl -I` 核对）。

### S-14 安全默认值（P1，1 人日）
- **做什么**：明确默认开/关：TLS 默认开、传输确认默认开、自动接受默认关、`--secure` 是否设为默认（建议：首次运行向导里让用户选「个人/公用」）。
- **验收标准**：默认安装后走一遍，必须经过「确认传输」与「信任设备」两步；文档写明每个开关的默认值与影响。

### S-15 发布完整性（P2，2 人日）
- **做什么**：EXE 代码签名（自签亦可，附公钥指纹）；APK 加 v3 签名；Release 附 `SHA256SUMS.txt`（已有）；生成 SBOM 或依赖清单。
- **验收标准**：`signtool verify` / `apksigner verify` 通过；下载页给出校验步骤。

### S-16 威胁模型与 SECURITY.md（P2，1 人日）
- **做什么**：写清信任边界（同一局域网、配对码、设备指纹）、防护目标（防窃听、防冒名、防误收）、**不防什么**（同网段主动攻击者、已被控制的终端、物理接触）；说明「个人模式可浏览整机」的边界与 `--secure` 差异；给出漏洞报告渠道。
- **验收标准**：SECURITY.md 进仓库；README 链接过去；威胁模型里每条假设都能对上代码位置。

## 四、明确不做（防止范围爆炸）

| 不做 | 理由 |
|---|---|
| 公网 CA 证书 / 域名 | 与「局域网直连、不联网」定位冲突 |
| 端到端加密（应用层再套一层） | TLS 已覆盖局域网威胁模型；再加一层只增延迟 |
| 账号体系 / 云端密钥托管 | 定位是「无账号」，引入即变质 |
| 防得住同网段主动 MITM 的强认证 | 需要预共享密钥或带外验证，超出个人工具范围；如实写进威胁模型 |
| 改「个人模式可读整机」的既有行为 | 属产品设计，不在本轮安全范围；只在文档写清 |
